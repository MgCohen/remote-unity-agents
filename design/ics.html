01

The problem

Set an agent a real goal and it doesn't just execute — it discovers. No plan survives a long run intact.

There's always something you couldn't see up front: a learning, a constraint you hit, a tweak. So you record it — back into the goal, back into the guardrails. Sensible, one at a time.

But it compounds. Every step writes a little more into the instructions, and the more you write, the further they drift from where they started. Far enough in, a guardrail has been quietly rewritten and a goal has shifted — and you're steering by something you no longer recognize or trust. That's the failure: not a bad first plan, but a good one that rotted as it grew.

02

What an anchor is

An anchor flips the instinct. It doesn't tell the agent what to do — it fixes what must stay true and fences off what not to do.

There are infinite ways to build something, and you can't pick the right one up front. But you almost always know what you don't want. So an anchor is mostly boundaries — non-goals, invariants, forbidden moves. It leaves the path open and walls off the cliffs.

Brittle — a direction“Add a Redis cache in front of the query.”
Robust — a guardrail“Reads must stay under 50ms; don't add a new datastore.”

And it doesn't live in one blob. An anchor separates concerns, so each part stays small and easy to maintain — the durable why (Intent), the guardrails (Constraints), and the bar for done (Success). That split is the whole artifact: I · C · S, one page.

03

How it works

Work happens at a scope — usually a slice of a feature. But that slice sits inside a feature, inside a domain, inside the project, and each level has its own anchor.

So starting a piece of work is a climb. You stand at your slice, walk up the scope, gather every anchor on the way, and compile them into one. That single compiled anchor governs the work — the project's non-negotiables, the domain's, the feature's, and this slice's, reconciled into one page instead of four documents the agent has to juggle.

Fig. 2  ·  climb the scope, compile every anchor into one

Once compiled, the anchor is fixed — and every activity loops back to it. Planning derives from it, building checks against it, review judges by it. Nothing runs off and forgets it.

Fig. 3  ·  every activity reads from the anchor and re-checks against it

04

Freeze — and the gate

Compiled, the anchor is fixed. The agent works inside it and never edits it — that's what stops the rot from section 01. Nothing you ship can quietly rewrite what you steer by.

But a hard freeze is its own trap. You started the run because you don't know everything yet — so if the anchor can never move, the first real discovery leaves you locked to something you now know is wrong.

So the freeze is gated, not absolute. The anchor changes only through a deliberate, human-approved amendment: the agent can propose, never approve; the default is to work within it; moving a guardrail is rare and conscious. It's the same governance the repo already applies to its protected paths.

05

Principles

Each rule traces to a finding or a decision — cited, so the reasoning survives.

P1

Lead with the negatives

Every beneficial rule in the 5,000-run study was a prohibition (“do not X”); every harmful one a directive (“do X”). Constraints are boundaries — procedure belongs in the plan.

→ Guardrails Beat Guidance
P2

One page, on purpose

Specification cost is U-shaped: too little defers it downstream, too much rebuilds waterfall. The optimum is a checkable middle. If it's growing into a PRD, it's stopped being an anchor.

→ Eisele · the U-curve
P3

Success is the review bar

Phrase it as observable outcomes with stable IDs (SC-1, SC-2) so reviews, tests, and PRs cite the exact criterion. Never “works well.”

→ NL-fixture boundary conditions
P4

Trace to evidence

Where a constraint has a durable source — an oracle item, an ADR, an observed friction — cite it. A constraint that traces to nothing is just opinion.

→ IntentSpec · ProductSpec
P5

Force the non-functional

Real agent files carry security and performance only ~15% of the time. The Constraints surface forces exactly the budgets everyone else forgets.

→ Agent READMEs corpus
P6

Scope it in / out / cut

Name what's included, deliberately excluded, and considered-then-dropped. Each line stands alone as a guardrail an agent can act on.

→ ProductSpec
