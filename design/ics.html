01

The drift problem

Set an agent a real goal and it doesn't just execute — it discovers. And what it discovers has to go somewhere.

Every long run turns up something you couldn't see up front: a limitation, a correction, a better idea. Sensibly, you write it down — into the goal, into the guardrails. But each note nudges the instructions a little, and the notes compound. Lap after lap, the thing you're steering by absorbs the very drift it was meant to prevent, until a guardrail has been quietly rewritten and you can no longer trust it. The failure isn't a bad first plan — it's a good one that rotted as it grew.

02

What an anchor is

An anchor doesn't script what to do. It fixes what must stay true and fences off what not to do.

There are infinite ways to build something, and you can't pick the right one up front — but you almost always know what you don't want. So an anchor leans on boundaries: non-goals, invariants, forbidden moves. It leaves the path open and walls off the cliffs.

Whatever you write is law. The preference for boundaries is about the mix, not the strictness — a positive "do X" is allowed when you truly need it, but used sparingly, because specific directions rot as work branches: "always use this colour" becomes a bug ten steps later on a sub-feature where it no longer makes sense. Negative and positive alike, once written, bind.

Prefer — a boundary“Reads must stay under 50ms; don't add a new datastore.”
Allow, sparingly — a direction“Use the existing Redis instance for the cache.”

And an anchor separates concerns — the durable why (Intent), the laws (Constraints), the bar for done (Success). That split is the next section's whole point.

03

Separate files, not one

Intent, Constraints, and Success are separate artifacts — not sections of one document.

Keeping them apart earns three things a single blob can't. Nothing bloats the context — you load only the concern you need. Reads are deterministic: open the Success file and everything in it is success, with nothing to hunt for. And because each file holds one kind of thing, a rubric or eval can check it — that a constraint reads like a constraint, that success is actually measurable.

intent.md
The durable why + North Star.
constraints.md
The laws — mostly what not to do.
success.md
Checkable outcomes, the review bar.
_rollup.md
Auto-generated summary of the tree.

How many files is your call — one page can hold all three when the work is small. Three (plus the optional auto-generated rollup) is the default because it keeps each concern clean and separately checkable.

04

Nesting & compiling

Work happens at a scope — a slice of a feature — and each scope can carry its own anchor.

A slice sits inside a feature, inside a domain, inside the project. Anchors can nest along that line: the higher ones are broad and rarely move; the deeper ones are specific and more ephemeral, thrown away when the slice is done. When you start a piece of work, you can compile the stack — walk up the scope, gather each anchor, and reconcile them into one that governs this task.

Fig. 2  ·  climb the scope, compile the anchors into one
Both are tools, not rules: nest when a scope earns its own anchor, compile when a task needs one. A single flat anchor is fine too.
05

Freeze & the gate

The anchor is fixed: the agent works inside it and doesn't edit it as it goes. That's what breaks the loop in section 01.

But it can't be frozen solid — you started the run because you don't know everything yet, and real discoveries should be able to move it. The agent will reach to fold each new insight straight into the anchor. So the guardrail sits on that reach: it detects the attempt, stops it, and warns you to decide. Nothing changes the anchor silently, and you're not left to catch it later by reviewing thousands of files.

What the research shows

The approach isn't only intuition — three independent findings back its core moves.

5,000 runs
A controlled study of coding agents: the rules that helped were boundaries (“do not X”); the ones that hurt were directions (“do X”).
Guardrails Beat Guidance
~15%
Share of real agent instruction files that mention security or performance at all — the constraints that matter most are the ones most often missing.
Agent READMEs corpus
U-shaped
Specification cost. Under-specify and the work leaks downstream; over-specify and you rebuild waterfall. The optimum is a small, checkable middle.
